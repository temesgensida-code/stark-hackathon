# STARK Changelog - 2026-10-07

**Built:**
- Backend: papers, documents, ai and notes modules on FastAPI with Postgres, Redis and an RQ parse worker. Scholarxiv Papers API for search, Router API for summaries and cited answers. A section parser that reads two-column PDFs in order.
- Frontend: home with search and upload, the paper reader (sections, caret, summaries, Q&A with source jumps, notes), the notes page with six-key Braille input, and a typed API client.
- Voice: ten Voxide actions (search, open, overview, section navigation, read, summarize, ask, add note, show in Braille) with Alt+V to talk.
- Braille: display keys now drive the app. Routing keys move the caret, panning past the end goes to the next section, Perkins typing fills the focused field. One language setting (English, Amharic, Afaan Oromoo) sets the Braille code, the AI language and the voice language. BRF download for any section.
- Quality: 48 API tests (in Docker with Liblouis), 21 web unit tests (4 of them need Liblouis and were not run on the Windows machine), 10 browser tests including axe-core accessibility checks on four pages.
- Docker Compose runs the whole stack, including the web app.

- Search from the Braille display: type a search on the Braille keys, Enter runs it, rocker or pan moves through results shown on the display, a routing key opens one. Enter alone lists your saved papers.
- A Braille bar on every page shows what is on the display; "Show in Braille" now says what it showed, on every page and by voice.

- The reader works from the Braille display alone: Space + S summarizes, Space + O gives the overview, Space + Q asks a question, Space + N saves a note, Space + R returns to the text, Space + H goes home, Space + L lists the commands. Results appear on the display. The bridge now reports Space + dots as commands (tested with real BrlAPI in Linux).

**Changed:**
- Fixed: every key on the virtual display was handled twice (a rocker press skipped a result; "pdf" was typed as "ppddff"). Found by the new Braille search tests.
- Docker: containers restart when Docker does, stop in under a second instead of being killed after 10, and health checks no longer flood `docker events`.
- The virtual display now runs in the browser and reconnects by itself; before, it died silently when the API restarted.
- Voice errors are announced. The Voxide project hit its usage limit during testing; the page now says so instead of staying silent.
- The reader's routing keys used the display cell index as a text index. They now go through the Braille manager, which maps cells to text correctly.
- Color contrast fixed on the primary button and the display simulator (axe found both).
- The open display dock no longer covers page controls.

**Cut or postponed (and why):**
- Login: postponed until the demo flow is tested (AD-15).
- Docling: not installed; the lighter PyMuPDF parser is used and tested on two real papers.
- Real Braille hardware: no device available yet; everything was tested with the virtual display.
- Voice end to end: the widget loads and the actions are registered, but nobody has spoken to it yet.

**Known limits:**
- Afaan Oromoo AI answers are weak (the model mixes English terms). Needs a native speaker's review.
- Amharic Braille cannot tell two letters apart (ቋ and ቇ share the same cells in Liblouis's table).
- arXiv can take over a minute to serve a PDF; import papers before a demo.
